# CoK OSM Importer

Импортирует данные [OpenStreetMap](https://www.openstreetmap.org) (дороги, реки, озёра, леса,
поля/посадки, деревья, здания) в файл карты редактора [Canvas of Kings](https://store.steampowered.com/)
(`.mommap`). Сделано чтобы превратить реальное место в основу для настольной ролевой карты, а не
для точной картографии.

English version: [README.md](README.md)

## Что импортируется, а что нет

**Импортируется:** дороги (как дорожные пути CoK), реки/ручьи (водные сплайны), озёра/пруды
(водные плоскости), лес/кустарник (лесные плоскости — CoK сам заполняет их деревьями процедурно,
мы не расставляем их вручную), поля/сады/виноградники ("посадки", тип плоскости), заборы/стены/
палисады, точечные деревья, и здания (очень грубо — см. предупреждения ниже).

**Пока не импортируется:** изгороди (у CoK для них своя система россыпи кустов, которую не удалось
разобрать), дыры в мультиполигонах (озеро/лес с островом внутри импортируется так, будто острова
нет — то есть "море вокруг острова" тоже не получится), relation-маршруты (route), реальный рельеф
(всё ставится на `y = 0`; используй собственные инструменты рельефа CoK после импорта, если нужен
ландшафт). Полный список известных проблем и идей — в [TODO.md](TODO.md), issue/PR приветствуются.

## Что нужно

- [.NET 10 SDK](https://dotnet.microsoft.com/download) или новее.
- OSM XML-экспорт нужной территории (вкладка "Export" на [openstreetmap.org](https://www.openstreetmap.org),
  [Overpass Turbo](https://overpass-turbo.eu/) или аналог — нужен `.osm`/`.xml`, не `.pbf`).
- Опционально — файл `.mommap`, который послужит базовым шаблоном (ради его настроек освещения/
  окружения — см. [Импорт без шаблона](#импорт-без-шаблона), если такого файла нет). Подойдёт
  любая настоящая карта CoK — твоё сохранение или что-то скачанное из Workshop в игре.

В репозитории намеренно нет `.osm`/`.mommap`-файлов (в `.gitignore`) — это либо большие личные
данные, либо чужой карточный контент, который не этому проекту распространять. Принеси свои.

## Быстрый старт

```
dotnet run --project src/CoK.OsmImporter.Cli -- ^
  --osm my-city.osm ^
  --template template.mommap ^
  --center 53.690,88.063 --radius 300 ^
  --scale 10 ^
  --out my-map.mommap
```

(`^` — символ переноса строки в `cmd` на Windows; в PowerShell используй `` ` ``, в bash/Git Bash — `\`.)

Команда читает `my-city.osm`, сохраняет освещение/настройки бумаги из `template.mommap`,
импортирует только область радиусом 300м вокруг указанных координат, сжимает реальные метры в
юниты карты в соотношении 10:1, и пишет `my-map.mommap`. Открой этот файл в Canvas of Kings.

## Справочник по флагам CLI

```
cok-osm-import --osm <file.osm> --out <file.mommap> [опции]
```

| Флаг | Обязателен | По умолчанию | Значение |
|---|---|---|---|
| `--osm <путь>` | да | — | Исходный OSM XML-файл. |
| `--out <путь>` | да | — | Путь для выходного `.mommap`. |
| `--template <путь.mommap>` | нет | пустой холст | Базовая карта для сборки — см. ниже. |
| `--bbox <minLat,minLon,maxLat,maxLon>` | нет | весь файл | Явный прямоугольник координат для импорта. |
| `--center <lat,lon>` + `--radius <метры>` | нет | весь файл | Импорт круга (как bbox) вокруг точки. Взаимоисключим с `--bbox`. |
| `--profile <full\|base>` | нет | `full` | `full` = дороги+вода+лес/поля+деревья+здания. `base` = то же самое без зданий. |
| `--scale <метровНаЮнит>` | нет | `1.0` | Сколько реальных метров представляет один юнит карты CoK. `--scale 10` сжимает всё в 10 раз. |
| `--simplify <юниты>` | нет | `2.0` | Допуск упрощения линий, в **юнитах карты на выходе** (не зависит от `--scale`). Увеличь, если CoK ругается "path invalid". `0` отключает упрощение. |
| `--merge <append\|replace>` | нет | `append` | `append` добавляет импортированное к существующему содержимому `--template`. `replace` сначала очищает объекты/пути (настройки освещения/бумаги остаются). |
| `--mapping <путь>` | нет | встроенный | Использовать свой конфиг маппинга тег→ассет вместо встроенного по умолчанию — см. [Настройка маппинга](#настройка-маппинга). |
| `--init-mapping <путь>` | нет | — | Записать встроенный конфиг маппинга по умолчанию в `<путь>` и выйти (не требует `--osm`/`--out`). Отредактируй и передай обратно через `--mapping`. |
| `--unmapped-report <путь>` | нет | — | Записать CSV со всеми комбинациями тегов, для которых не нашлось правила — чтобы видеть, что было пропущено. |
| `--help` | нет | — | Показать справку. |

### Выбор области

Если не указать ни `--bbox`, ни `--center`/`--radius` — импортируется **весь** файл целиком. Для
чего-то крупнее небольшого посёлка это даёт огромную карту — при таком запуске CLI выводит
предупреждение. На практике почти всегда нужен `--center`/`--radius` (несколько сотен метров куда
ближе к тому, что реально представляет собой рукописная настольная карта) либо руками подобранный
`--bbox`.

### Импорт без шаблона

Без `--template` инструмент стартует с пустого холста — но с **настоящими** настройками освещения/
тумана/цвета воды/бумаги по умолчанию (скопированы из рабочей карты CoK на этапе сборки), а не с
пустыми. Более ранняя версия этого инструмента писала туда реально пустые настройки, что CoK
рисует как полностью неосвещённый, прозрачный, серый экран — если у тебя именно так, значит сборка
устаревшая, пересобери из исходников.

### Настройка маппинга

`mapping.json` — это место, где живут все решения "тег OSM X → префаб CoK Y", в виде обычного
редактируемого JSON — в коде импортера ничего не зашито жёстко. Получить копию:

```
dotnet run --project src/CoK.OsmImporter.Cli -- --init-mapping my-mapping.json
```

затем отредактируй и передай обратно через `--mapping my-mapping.json`. В начале файла есть
секция `notes`, отмечающая места, где я **гадал**, а именно:

- **Дороги** (секция `roads`): у `pa_road.tscn` есть 7 визуальных вариантов в CoK (`path_type`
  17–23), и по одним данным невозможно понять, какой из них выглядит как булыжная мостовая, а
  какой — как грунтовка. По умолчанию иерархия `highway=*` из OSM раскидана по ним по разумному
  предположению. Открой CoK, нарисуй по одному сегменту каждого `path_type`, посмотри как они
  реально выглядят, и перепривяжи значения `highway` в `"roads"` соответственно.
- **Здания** (секция `buildings`): у CoK нет префабов под большинство реальных категорий зданий/
  магазинов. По умолчанию всё падает на обычные хижины, кроме нескольких значений тегов
  (`amenity=pub/bar/restaurant/cafe` → таверна, `shop=*`/`amenity=marketplace` → рыночные лотки).
  Добавляй новые записи в `rules` (проверяются сверху вниз, побеждает первое совпадение) по мере
  того как найдёшь префабы CoK, которые подходят лучше.

Всё остальное в файле (какие значения `natural`/`landuse`/`waterway` считаются лесом, водой, полем,
какой префаб использует река/стена/забор/дерево) подтверждено на реальных данных CoK — эти значения
обычно трогать не нужно, хотя можно дописывать новые значения в списки (например, синонимы
`landuse` для полей), если в твоих OSM-данных встречаются теги, которых нет в списке по умолчанию.
Запусти с `--unmapped-report unmapped.csv`, чтобы увидеть, какие именно комбинации тегов ни на что
не попали — так понятно, что стоит добавить.

## Известные ограничения / на что обратить внимание

- **Лесные/кустарниковые/полевые зоны могут не отображаться.** В тестах озёра (water plots)
  рендерились корректно, а лес (тем же самым кодом!) — нет. Похоже на ограничение самой игры на
  ранней стадии разработки, а не баг импортера, но это не доказано железно. Если лес не
  появляется — проверь, рендерится ли вручную нарисованная лесная зона на иначе нетронутой карте
  CoK. Если и там не видно — дело не в этом инструменте. См. [TODO.md](TODO.md).
- **Нет "моря вокруг острова".** Плоскость океана в CoK требует дырку посередине (остров), а
  импортёр пока умеет только простые полигоны без дырок. См. [TODO.md](TODO.md).
- **Импорт большой площади может быть буквально огромным** относительно того, что вообще
  представляют карты CoK. Пример-деревня самой игры — это примерно 200×200 юнитов карты; реальный
  город в масштабе 1:1 — это тысячи юнитов. Используй `--center`/`--radius` и/или `--scale`, чтобы
  привести размер к тому, что реально нужно (проходимая деревня/район, а не целый город в
  геодезическом масштабе).
- **Ошибки "path invalid" на реках/дорогах/стенах** почти всегда означают, что инструменты путей
  CoK отвергают геометрию из-за плотности точек или резких углов — подними `--simplify` (попробуй
  4–5) и импортируй заново.
- **Рендеринг рек — это лучшая попытка реконструкции, всё ещё не до конца рабочая на реальных
  данных.** Нужные поля подтверждены на вручную нарисованных тестовых реках в редакторе CoK (а не
  по официальной документации) — эта часть верна, но импортированные из OSM реки всё ещё рисуются
  тонкими, и CoK всё ещё жалуется "path invalid" даже после повышения `--simplify`. Открытая
  проблема, см. [TODO.md](TODO.md).
- Здания ставятся в центроид контура с грубым направлением (по самой длинной стороне контура) и
  небольшим случайным разбросом масштаба — это не точное совпадение с исходным размером/формой
  здания в OSM.
- Выбор префаба дерева/здания детерминирован (зависит от id OSM-элемента), так что повторный
  запуск с тем же `mapping.json` всегда даёт одинаковый результат.

## Структура проекта

```
src/CoK.OsmImporter.Core/   библиотека классов — парсинг OSM, гео-проекция, модель данных .mommap,
                             каталог ассетов, конфиг маппинга и сам конвейер конвертации
src/CoK.OsmImporter.Cli/    консольная точка входа (это то, что реально запускается)
tests/                       набор тестов xUnit, включая round-trip тесты на реальном
                             template.mommap и интеграционные тесты конвейера конвертации
```

## Контрибьютинг

Issue и PR приветствуются — в [TODO.md](TODO.md) приоритизированный список известных открытых
проблем, включая те, где просто нужен человек, реально посмотревший на редактор CoK (секции

[Настройка маппинга](#настройка-маппинга)). Если будешь реверс-инженерить ещё какой-то тип ассета,
самый надёжный способ, что сработал здесь: нарисуй руками маленький пример в редакторе CoK,
сохрани, и сравни сырой JSON с тем, что генерирует этот инструмент для того же объекта — именно так
были разгаданы форматы дорог и рек, а не по документации (её просто нет).
